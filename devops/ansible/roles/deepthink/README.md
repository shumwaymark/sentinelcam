# DeepThink Role

Provisions the ML training node (deepend) for facial recognition model training.

## Purpose

DeepThink sets up the Jetson Nano as a training environment for the SentinelCam facial recognition
pipeline. The Jetson Nano is an embedded ARM64 device chosen for low-power always-on availability
(~10W) rather than training speed — overnight runs are acceptable for infrequent retraining.

This is **not** an application service role. It provisions the environment (venv, packages, directory
structure) and deploys the training scripts and notebooks that are executed manually.

## The Training Pipeline

The facial recognition pipeline spans multiple nodes:

```
Outposts → CamWatcher → Sentinel (FaceSweep/FaceDataUpdate)
                              ↓
                   facelist.csv + facedata.hdf5
                              ↓
               Datasink (model registry staging)
                              ↓
                  DeepEnd (SVM training via Papermill)
                              ↓
              facemodel.pickle + baselines.hdf5
                              ↓
               Model Registry → deploy to Sentinel
```

Key artifacts:
- **facelist.csv** — curated training selections (maintained on sentinel, curated via twister notebooks)
- **facedata.hdf5** — OpenFace embeddings generated by sentinel's FaceDataUpdate task
- **facemodel.pickle** — trained SVM classifier
- **baselines.hdf5** — per-person distance thresholds

Training data flows: sentinel → datasink staging → deepend (rsync pull). Trained models flow back
via `upload_and_deploy.sh` to the model registry on the datasink, then deploy to sentinel via Ansible.

See [Gamma4 Workflow](../../../../docs/GAMMA4_WORKFLOW.md) for the current end-to-end procedure and
[Facial Recognition Pipeline](../../../../docs/FACIAL_RECON_LEARNING.md) for architecture details.

## Dependencies

- **Datasink** (data1) — model registry storage and training data source
- **Sentinel** — generates embeddings and facelist via FaceSweep/FaceDataUpdate tasks
- SSH key access from deepend to datasink for rsync

Does **not** use sentinelcam_base. The Jetson Nano has its own JetPack SDK environment; CUDA and
system Python are left untouched.

## Configuration

### Defaults

| Variable | Default | Purpose |
|----------|---------|---------|
| `deepthink_python38_enabled` | `true` | Install Python 3.8 from deadsnakes PPA |
| `deepthink_venv_path` | `~/.virtualenvs/ml-training` | Training venv (separate from JetPack) |
| `deepthink_papermill_enabled` | `true` | Install Papermill for notebook execution |
| `jetson_max_power_mode` | `false` | `nvpmodel -m 0` for max performance |
| `jetson_headless` | `true` | No GUI to save GPU memory |

### Venv Strategy

The role prefers an existing `py3cv4` venv (PyImageSearch standard with OpenCV). If not found, it
creates a new `ml-training` venv. When Python 3.8 is enabled, a separate `ml-training-py38` venv
is created for scikit-learn compatibility.

Installed packages: scikit-learn, pandas, h5py, papermill, jupyter, matplotlib, seaborn.

## Deployment

```bash
# Full setup (directories, venv, packages)
ansible-playbook playbooks/deploy-deepthink.yaml

# Verify
ansible ml_trainers -m command -a "ls -la ~/deepthink"
```

### Running a Training Job

```bash
# On deepend
# 1. Pull data from datasink
rsync -avz ops@data1:/home/ops/sentinelcam/model_registry/face_recognition/gamma4_staging/ \
  ~/deepthink/data/

# 2. Run training (~6hr overnight)
~/deepthink/train_face_model.sh 2026-01-15

# 3. Deploy to model registry
~/deepthink/upload_and_deploy.sh face_recognition 2026-01-15 \
  facemodel.pickle baselines.hdf5 facelist.csv facedata.hdf5
```

## Tags

| Tag | Scope |
|-----|-------|
| `python38` / `setup` | Python 3.8 installation from deadsnakes PPA |
| `venv` | Virtual environment creation |
| `packages` | ML Python package installation |
| `config` | Directory structure |
| `jetson` | Power mode configuration |

## File Structure (on target)

```
/home/<user>/
├── deepthink/
│   ├── notebooks/            # Training notebooks (Papermill templates)
│   │   └── output/           # Executed notebook output
│   ├── models/               # Trained model output
│   └── data/                 # Training data (rsync'd from datasink)
├── .virtualenvs/
│   └── ml-training/          # Training venv (or py3cv4 if present)
└── sentinelcam/logs/         # Training logs
```

### Templated Scripts

| Script | Purpose |
|--------|---------|
| `train_face_model.sh` | Runs Papermill against training notebook with versioned parameters |
| `upload_and_deploy.sh` | Uploads trained model to datasink registry, triggers Ansible deploy |
| `deploy_model.sh` | Legacy direct SCP deployment (pre-registry) |
